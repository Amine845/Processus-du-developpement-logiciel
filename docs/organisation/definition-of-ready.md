# Definition of Ready

Une user story est considérée prête pour un Sprint Planning lorsque les éléments suivants sont satisfaits.

## Checklist

- [ ] La valeur ou le besoin utilisateur est compris.
- [ ] La story est formulée du point de vue de l'utilisateur ou du système concerné.
- [ ] Les critères d'acceptation sont observables et testables.
- [ ] Le Product Owner a clarifié les questions fonctionnelles essentielles.
- [ ] La priorité est connue.
- [ ] Les dépendances sont identifiées.
- [ ] Les données ou maquettes nécessaires sont disponibles, ou leur création fait partie de la story.
- [ ] Les risques principaux sont visibles.
- [ ] Les développeurs ont produit une estimation collective.
- [ ] La story semble réalisable dans un sprint.
- [ ] La méthode de démonstration est connue.

## Exceptions

Une story non prête peut être sélectionnée uniquement si :

- l'incertitude est explicitement identifiée ;
- l'équipe estime que l'objectif du sprint reste réaliste ;
- une action de clarification est planifiée ;
- le risque est consigné dans le document du sprint.

La Definition of Ready aide la préparation, mais ne doit pas devenir une barrière bureaucratique empêchant tout apprentissage.
